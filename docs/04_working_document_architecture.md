# 工作文档架构

## 文档分层

### 治理层

- `00_project_charter.md`：目标、范围、非目标和成功标准。
- `05_decision_log.md`：数据版本、技术选型和不可隐式更改的决定。

### 技术合同层

- `01_data_sources_and_contracts.md`：路径、字段、图层和读写规则。
- `02_agent_orchestration.md`：节点、路由、工具和输出结构。
- `03_model_and_secret_policy.md`：Provider、模型角色和密钥管理。

### 执行层

- `06_work_log.md`：按日期记录完成项、验证结果、问题和下一步。
- `07_portable_data_spec.md`：便携数据包、编号和字段规范。
- 后续新增 `08_evaluation_plan.md`：固定测试集和指标。
- 后续新增 `09_deployment_runbook.md`：本地与公开部署。
- 后续新增 `10_competition_material_map.md`：系统功能到申报书、说明书和视频的映射。

## 更新原则

1. 路径或版本改变，先更新 `config/data_paths.json`，再更新数据契约和决策日志。
2. Agent节点或路由改变，更新编排文档并增加决策记录。
3. API Key轮换只改外部秘密文件，不改文档和代码。
4. 每次形成可运行里程碑，在工作日志中记录命令、结果和已知限制。
5. 指标必须注明数据版本和测试集版本，禁止只写百分比而不写分母。
6. 竞赛文案不能成为工程真源；竞赛材料应从冻结配置和评价结果生成。

## 文件命名

- 稳定文档使用固定编号，不在文件名中堆叠“最终版”“最新版”。
- 运行产物使用 `YYYYMMDD_HHMM` 或语义版本号。
- 测试集、索引和公开演示子图必须记录来源版本。
